# Shared packages and design system

Shared packages avoid duplicating domain rules and UI behavior between the admin site, public site, and API. Each app imports source through its workspace dependency; packages generally build TypeScript output into `dist/` before the apps run.

| Package | Name | Responsibility |
| --- | --- | --- |
| `packages/ui` | `sanui` | Reusable React components, hooks, styles, and CSS design tokens. Intended to be the independently consumable UI kit. |
| `packages/map-engine` | `@vstudio/map-engine` | SVG layout canvas, viewport zoom/pan, selection, rectangle/polygon drawing, vertex editing, fullscreen controls, and coordinate conversion. It does not own unit business data. |
| `packages/types` | `@vstudio/types` | Shared TypeScript domain types, unit statuses, legal status transitions, and centralized status colors. |
| `packages/validation` | `@vstudio/validation` | Reusable Zod schemas for projects, units, geometry, CSV rows, and layout metadata. |
| `packages/auth` | `@vstudio/auth` | Central role/permission definitions and authorization helpers. |
| `packages/api-client` | `@vstudio/api-client` | Typed fetch wrapper for web apps, with base URL, session credentials, JSON errors, and endpoint functions. |
| `packages/config` | `@vstudio/config` | Environment parsing/validation shared by server processes. |
| `packages/utils` | `@vstudio/utils` | Formatting helpers and sample/demo data used by UI screens. |
| `packages/eslint-config` | `@vstudio/eslint-config` | Shared ESLint configuration. |
| `packages/tsconfig` | `@vstudio/tsconfig` | Shared TypeScript base configurations. |

## SanUI (`packages/ui`)

The source lives under `packages/ui/src/`. The package public entry is `src/index.ts`, which re-exports the components, hooks, utilities, and styles. Edit the source `.tsx`/`.ts` files and CSS; `dist/` is generated by the package build.

Build and check the package from the repository root:

```sh
pnpm --filter sanui build
pnpm --filter sanui typecheck
```

Workspace usage looks like:

```tsx
import { Button, TextField } from 'sanui'
import 'sanui/styles.css'
```

Design tokens are CSS custom properties prefixed with `--sanui-` in `packages/ui/src/tokens.css`. Components use these tokens so consuming apps can theme the library. `packages/ui/README.md` contains the minimal consumer example.

The package metadata currently exposes built files from `dist/`; its name is `sanui`, but the workspace uses local linking. Before an actual npm publish, confirm the desired npm name is available, review package metadata/license/version, build the `dist/` folder, and test a packed tarball in a separate consumer app. A package name in `package.json` alone does not mean it has been published.

## Map Engine (`packages/map-engine`)

The map engine receives shape geometry, dimensions, selection state, and callbacks. Admin supplies application data such as unit number and status. Public supplies the subset of units the public API response allows. The engine's geometry helpers are also tested in its package.

When making map changes, keep business fields out of the engine. For example, the engine should report “geometry changed”; the admin app decides how to validate and persist the unit.

## Shared status values

`packages/types/src/status.ts` defines legal status transitions. `packages/types/src/status-presentation.ts` centralizes labels and fill/text colors for both UIs. If a status is added or its color changes, update the shared type/config and review all API validation, database enum, filters, and status selectors.
